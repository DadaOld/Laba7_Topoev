## 2.2. Исходный код main.c

Для освоения инструментов был создан файл `main.c` с функцией `square` и функцией `main`.

```c
#include <stdio.h>

int square(int x) {
    return x * x;
}

int main() {
    int a = 5;
    int b = square(a);
    printf("%d\n", b);
    return 0;
}
```

Функция `square` принимает целое число и возвращает результат умножения аргумента на самого себя. В функции `main` значение `5` передается в `square`, после чего результат выводится через `printf`.

В IR без оптимизации присутствуют инструкции `alloca`, `store` и `load`. Это значит, что локальные переменные размещаются в памяти, а значения явно записываются и считываются. Также видно, что функция `square` вызывается отдельно.

## 2.5. Оптимизация IR

Сравнение IR до и после оптимизации показывает, что оптимизированное представление становится короче и ближе к SSA-форме. Переменные, которые при `-O0` размещались через `alloca`, после `-O2` не требуют явного хранения в памяти.

Основные изменения после оптимизации:

- удалены лишние `alloca`, `store` и `load`;
- короткая функция `square` была встроена в место вызова;
- выражение `square(5)` было вычислено заранее;
- вызов `printf` получает уже готовый аргумент `25`;
- поток управления остался линейным, поскольку в программе нет ветвлений и циклов.

## 3.6. Вывод по индивидуальному заданию

На уровне AST условный оператор if-else представлен узлом IfStmt с условием (BinaryOperator >), then-веткой (ReturnStmt с a) и else-веткой (ReturnStmt с b). Вызов функции max в main отображается как CallExpr с аргументами x и y.
В IR без оптимизации (-O0) компилятор сохраняет локальные переменные через alloca, store и load. Условный оператор реализован через icmp sgt и br i1 с тремя метками (then, else, merge), что создаёт разветвлённый CFG из четырёх базовых блоков.
После оптимизации -O2 лишние alloca, store и load удаляются, код переводится в SSA-форму. Ветвление br i1 заменено на встроенную функцию llvm.smax.i32 (intrinsic для signed maximum), которая выбирает большее из двух значений без условных переходов. В функции main результат max(10, 20) вычислен на этапе компиляции и подставлен как константа 20 в вызов printf.
Следовательно, LLVM выполняет локальное упрощение IR: устраняет ветвления, переводит в SSA-форму, применяет встроенные intrinsics и сворачивает константы. Однако функция max не исчезает полностью — она преобразуется в llvm.smax.i32, что позволяет сохранить её семантику при полном отсутствии ветвлений в CFG.

# 4. Дополнительное задание

Дополнительное задание рассматривает синтаксическую конструкцию **if-else** (условный оператор) из лабораторной работы №5.

В качестве конкретного тестового примера используется конструкция:

```c
if (a > b)
    max = a;
else
    max = b;
```

Оптимизации рассматриваются как локальные: они работают только внутри одной конструкции if-else и не анализируют другие части программы. Преобразования сохраняют семантику исходной конструкции.

---

## 4.1. AST конструкции

Для конструкции `if (a > b) max = a; else max = b;` AST можно представить в виде дерева:

```
ProgramNode
└── FunctionNode: max
    └── IfStmt
        ├── ConditionNode: BinaryOperator '>'
        │   ├── DeclRefExpr: a
        │   └── DeclRefExpr: b
        ├── ThenNode: CompoundStmt
        │   └── BinaryOperator '='
        │       ├── DeclRefExpr: max
        │       └── DeclRefExpr: a
        └── ElseNode: CompoundStmt
            └── BinaryOperator '='
                ├── DeclRefExpr: max
                └── DeclRefExpr: b
```

Узел `IfStmt` содержит:
- **ConditionNode** — условие (`BinaryOperator` `>`) с операндами `a` и `b`;
- **ThenNode** — ветка `then` (присваивание `max = a`);
- **ElseNode** — ветка `else` (присваивание `max = b`).

---

## 4.2. Упрощенное IR / TAC конструкции

Для одной конструкции if-else можно использовать трехадресное представление:

```
t0 = load a
t1 = load b
t2 = icmp sgt t0, t1        ; a > b ?
br i1 t2, label %then, label %else

then:
  store a, max
  br label %merge

else:
  store b, max
  br label %merge

merge:
  ; продолжение программы
```

Или в виде списка виртуальных инструкций:

| Блок | Инструкция | Операция | Операнд 1 | Операнд 2 | Результат |
|------|------------|----------|-----------|-----------|-----------|
| entry | LOAD | load | a | — | t0 |
| entry | LOAD | load | b | — | t1 |
| entry | ICMP | icmp sgt | t0 | t1 | t2 |
| entry | BR | br i1 | t2 | label %then | label %else |
| then | STORE | store | a | — | max |
| then | BR | br | label %merge | — | — |
| else | STORE | store | b | — | max |
| else | BR | br | label %merge | — | — |
| merge | PHI | phi | [%then, a] | [%else, b] | max |

---

## 4.3. Локальная оптимизация 1 — свертка констант в условии

Первая оптимизация выполняет **свертку констант** в условии if-else. Если условие является константным выражением, оно вычисляется на этапе компиляции, и весь if-else заменяется на соответствующую ветку.

<img width="793" height="951" alt="block_scheme1" src="https://github.com/user-attachments/assets/422a5d59-1005-4e49-a152-5943e8097df9" />


**Пример:** условие `5 > 3` всегда истинно → остаётся только then-ветка.

**Входной IR:**
```
t0 = 5
t1 = 3
t2 = icmp sgt t0, t1        ; всегда true!
br i1 t2, label %then, label %else

then:
  store 5, max
  br label %merge

else:
  store 3, max
  br label %merge

merge:
  ; продолжение
```

**Выходной IR (после свертки):**
```
; условие вычислено на этапе компиляции: 5 > 3 = true
; else-ветка удалена как недостижимая
store 5, max                  ; только then-ветка
; br label %merge — также удалён, если merge пустой
```

**Обоснование корректности:** константное выражение `5 > 3` всегда даёт `true`, поэтому else-ветка никогда не выполнится. Удаление недостижимого кода и подстановка константы сохраняют семантику.

---

## 4.4. Локальная оптимизация 2 — замена if-else на select (устранение ветвления)

Вторая оптимизация **приводит if-else к каноническому виду** — заменяет ветвление на инструкцию `select` (аналог `cmov`). Это устраняет условные переходы и упрощает CFG до одного базового блока.

<img width="613" height="761" alt="block_scheme2" src="https://github.com/user-attachments/assets/807b5527-4f13-453b-b1fc-5ef40cbfed6b" />

**Пример:** `if (a > b) max = a; else max = b;` → `max = select(a > b, a, b)`.

**Входной IR:**
```
t0 = load a
t1 = load b
t2 = icmp sgt t0, t1
br i1 t2, label %then, label %else

then:
  store t0, max
  br label %merge

else:
  store t1, max
  br label %merge

merge:
  ; продолжение
```

**Выходной IR (после замены на select):**
```
t0 = load a
t1 = load b
t2 = icmp sgt t0, t1          ; сравнение остаётся
t3 = select i1 t2, i32 t0, i32 t1   ; условное перемещение!
store t3, max
; br инструкции удалены — нет ветвления!
```

**Обоснование корректности:** инструкция `select` выбирает `t0` (значение `a`), если условие истинно, и `t1` (значение `b`) иначе. Это эквивалентно семантике if-else, но без условных переходов. CFG упрощается с 4 блоков до 1, что улучшает производительность за счёт отсутствия pipeline flush.

## 4.5. Вывод по дополнительному заданию

Для выбранной синтаксической конструкции **if-else** были описаны AST и упрощенное IR-представление. Рассмотрены две локальные оптимизации:

1. **Свертка констант** — вычисление константного условия на этапе компиляции с удалением недостижимой ветки;
2. **Замена if-else на select** — устранение ветвления путём замены `br i1` на инструкцию `select`, что упрощает CFG до линейной структуры.

Обе оптимизации работают внутри одной конструкции if-else и не требуют анализа других частей программы. Преобразования сохраняют семантику исходной конструкции: в первом случае удаляется код, который никогда не выполнится; во втором случае условный выбор реализуется без переходов, но с тем же результатом.

Сравнение IR показало, что при `-O0` компилятор сохраняет локальные переменные через `alloca`, `store` и `load`. После `-O2` код становится короче: лишние операции работы с памятью удаляются, а простые вычисления могут быть свернуты в константы.

# 6. Ответы на контрольные вопросы

## 6.1. Что такое Clang, и какова его роль в процессе компиляции программ?

**Clang** — это компилятор языков C, C++ и Objective-C. Он выполняет роль фронтенда: анализирует исходный код, строит AST, выполняет проверки и генерирует LLVM IR.

---

## 6.2. Что представляет собой LLVM и как он используется в современных компиляторах?

**LLVM** — это инфраструктура для построения компиляторов. Она содержит промежуточное представление LLVM IR, набор оптимизаций и средства генерации машинного кода для разных архитектур.

---

## 6.3. Чем отличается AST от LLVM IR?

**AST** отражает синтаксическую структуру исходной программы, а **LLVM IR** является более низкоуровневым промежуточным представлением, удобным для оптимизации и генерации машинного кода.

---

## 6.4. Для чего необходимо промежуточное представление IR?

IR позволяет отделить анализ исходного языка от оптимизации и генерации машинного кода. Благодаря этому одни и те же оптимизации можно применять к программам, написанным на разных языках.

---

## 6.5. Что делает инструкция alloca в LLVM IR?

Инструкция `alloca` выделяет память в стеке функции для локальной переменной. При оптимизации такие размещения часто удаляются или переводятся в регистровое представление.

---

## 6.6. Зачем нужна оптимизация кода?

Оптимизация нужна для уменьшения количества инструкций, удаления лишних вычислений, сокращения обращений к памяти, упрощения потока управления и повышения скорости выполнения программы.

---

## 6.7. Что такое SSA-форма?

**SSA-форма** — это форма представления программы, в которой каждая переменная получает значение только один раз. Она упрощает анализ зависимостей и применение оптимизаций.

---

## 6.8. Что такое CFG?

**CFG** — это граф потока управления. Его вершинами являются базовые блоки, а ребра показывают возможные переходы между ними.

---

## 6.9. Как представляются арифметические операции в LLVM IR?

Арифметические операции представлены отдельными инструкциями. Например, умножение целых чисел может быть записано как:

```llvm
mul i32 %a, %b
```

---

## 6.10. Почему функции в LLVM IR являются отдельными единицами анализа?

Функция имеет собственные аргументы, локальные переменные, базовые блоки и CFG, поэтому ее удобно анализировать и оптимизировать отдельно.

---

## 6.11. Что происходит с короткой функцией, если она вызывается один раз?

Оптимизатор может встроить такую функцию в место вызова. После этого становятся возможны дополнительные оптимизации, например свертка констант.

---

## 6.12. Какие преимущества дают IR и CFG по сравнению с анализом исходного текста на C?

IR и CFG имеют формальную структуру, поэтому в них проще анализировать зависимости, поток управления, использование переменных и достижимость кода.
